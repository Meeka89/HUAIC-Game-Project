# Proposed roadmap

Early May 2027 is the target timeframe. These are proposed phases, not dated commitments or promised features. Meetings occur approximately 1–2 times per month, with flexible work between meetings. Adjust scope to the people and time available.

| Proposed phase | Concrete outcome |
| --- | --- |
| Planning | A reviewed game plan covering concept, smallest playable version, exclusions, engine choice with reasons, remaining questions, and small next tasks. Aim for this by the next meeting; a prototype is not required then. |
| Tiny playable prototype | The agreed core interaction and player goal can be tried in one small single-player experience. Setup/run instructions exist, and a packaged build is available for nontechnical testers. |
| Iterative improvement | Feedback from the prototype guides a small set of agreed changes. Each change has completion criteria and can be reviewed independently. |
| Testing and polish | A candidate build has been played by testers, serious known problems are resolved or documented, and controls, instructions, asset permissions, and credits have been reviewed. |
| Release decision | Maintainers and participants review a playable, tested game and decide whether, where, and when to release it, resolving licensing and ownership questions before publication. Steam remains a possible stretch goal. |

At each review, agree on **the next milestone**, split it into small tasks, identify dependencies, and invite volunteers. Do not fill a speculative gameplay backlog in advance. Keep the smallest playable version achievable; cut optional features when needed instead of assuming more volunteer time.

Start with [INITIAL_TASKS.md](INITIAL_TASKS.md). Record decisions in [DECISIONS.md](DECISIONS.md) and build feedback using [PLAYTESTING.md](PLAYTESTING.md).
